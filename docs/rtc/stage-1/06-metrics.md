# 06 · 核心指标

> 📍 阶段一 · 知识整理 06 ｜ 定位：指标字典 + QoS/QoE 分析框架，后续每个阶段都会回头引用

## 为什么先学指标

没有度量就没有优化。学协议之前先建立指标坐标系，之后每个技术方案都能回答两个问题：**它改善了哪个指标？代价是牺牲了哪个指标？**

## 播放体验指标（QoE 侧）

| 指标 | 定义 | 说明 |
| --- | --- | --- |
| **首开时间** | 点击播放 → 首帧上屏 | 点播 / 直播的第一指标 |
| **秒开率** | 首开 < 1s 的播放次数占比 | 首开的分布化表达 |
| **卡顿率** | 发生卡顿的播放占比，或卡顿时长 / 总观看时长 | 「卡顿」的定义要先统一（如渲染间隔超阈值 / 缓冲区耗尽） |
| **端到端时延** | 采集端打时间戳 → 播放端比对 | 直播核心指标，注意与「首开」是两回事 |
| **播放成功率** | 成功起播次数 / 总次数 | 失败要按错误类型分类（网络 / 解码 / 404） |
| **音画同步偏移** | 音频与视频呈现的时间差 | 人耳可感知阈值约在几十毫秒量级，RTC 场景关键 |

## 网络与服务指标（QoS 侧)

| 指标 | 含义 |
| --- | --- |
| 丢包率 | 传输中丢失的数据包比例 |
| 抖动（Jitter） | 包到达间隔的波动程度 |
| RTT | 往返时延 |
| 码率达标率 | 实际下载速度能否覆盖播放所需码率 |
| CDN 命中率 / 回源率 | 边缘分发的效率 |

## QoS 与 QoE 的关系

- **QoS**：网络与服务端的客观质量（丢包、抖动、RTT…）。
- **QoE**：用户主观体验的度量（卡不卡、开得快不快、看着爽不爽）。

关系链条与反例：

- QoS 差 →（大概率）QoE 差：弱网必然卡顿。
- **QoS 好 ≠ QoE 好**：网络满分，但 MP4 的 moov 在文件尾 → 首开照样烂。这是架构问题，不是网络问题——单看 QoS 永远找不到根因。

实践框架：**QoE 指标做北极星，QoS 指标做归因线索**。

## 指标归因速查

| 指标异常 | 常见原因 | 责任环节 |
| --- | --- | --- |
| 首开慢 | moov 后置、GOP 太长、CDN 未命中、预加载不足 | 封装 / 编码 / 分发 |
| 卡顿 | 带宽不足、抖动大、码率自适应不及时、解码性能不够 | 传输 / 播放端 |
| 时延大 | 切片大、缓冲深、链路长、协议选错 | 协议 / 架构 |
| 音画不同步 | 时间戳错乱、主时钟策略缺失 | 全链路 |

这张表会在阶段二、三的学习中不断被验证和充实——学每个协议时都想一想：它影响表里的哪一格。

## 指标间的取舍

优化任何指标前先问：**牺牲的是谁？**

- 缓冲深 = 流畅 ↑ 时延 ↑（直播的经典矛盾，见上一章）。
- RTC 内：码率 ↑ 画质 ↑，但网络一抖质量崩塌 → 拥塞控制动态平衡。
- 分发成本 vs 体验：更高清 = 更多带宽 = 更贵，产品决策永远在中间找点。

## 关键要点

- 五个必会指标：首开时间、秒开率、卡顿率、端到端时延、播放成功率。
- QoE 是北极星，QoS 是归因线索；QoS 好不代表 QoE 好。
- 指标之间是权衡关系，不是都要最优。
