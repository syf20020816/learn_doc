# 阶段五：综合串联与进阶视野

> ⏱️ **学习时间**：2 周（每天 1~2 小时，约 20 学时） · 累计周期：第 17~18 周

## 阶段目标

把前四个阶段的知识串联成完整图景：能对任意一条音视频链路做时延拆解，能设计 QoE 指标体系，并通过输出一篇综述或一张全景图来检验学习成果。

## 知识点清单

### 全链路时延拆解

- [ ] 从采集到渲染逐段列出时延来源：采集缓冲 / 编码等待 / 封包 / 网络 / 去抖动 / 解码等待 / 渲染
- [ ] 针对每段说出 1~2 个常见优化手段（概念层）

### QoE 指标体系

- [ ] 首开、卡顿率、秒开率、端到端时延、音画同步偏移的定义与测量思路
- [ ] 指标如何采集与归因（概念层面）

### 行业视野

- [ ] 主流 RTC 云厂商公开架构对比：SFU 选型、全球边缘节点、传输协议栈
- [ ] 直播与 RTC 融合的趋势：超低延迟直播、MoQ 在其中的位置

### 产出

- [ ] 写一篇学习综述，或画一张「从采集到渲染」的全景图
- [ ] 回顾五个阶段的知识点清单，把未勾选项补齐

### 后续路标（仅指路，不在本站范围）

- [ ] 编解码深入：H.264 / HEVC / AV1 / Opus 原理
- [ ] 引擎与客户端：WebRTC 源码、FFmpeg 实战
- [ ] 服务端：SRS / mediasoup / Pion / webrtc-rs 源码

## 推荐资料

- [quic.video](https://quic.video/) —— 回顾 MoQ 与未来趋势
- [《WebRTC for the Curious》](https://webrtcforthecurious.com/) —— 收尾重读一遍，体会会完全不同
- [SRS 官方文档](https://ossrs.net/) —— 用一个真实开源项目验证你的全链路认知
- [mediasoup 文档](https://mediasoup.org/documentation/) —— 主流 SFU 的架构参考

## 阶段自测

1. 画出端到端时延的分段图，标出占比最大的两段及原因。
2. 如果为「跨国 1v1 面试」产品设计 QoE 指标，你会选哪几个？为什么？
3. 用 5 分钟向新同事讲清「直播」和「RTC」的架构区别，你会怎么讲？
